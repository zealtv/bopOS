# Cards implementation summary

The four implementation children deliver the ratified design without server,
OSC, manifest, Show, or Pure Data changes:

1. Control persists a unique target set and derives card order.
2. Remote derives every target without picker or presets.
3. Both hosts share the Seats-map identity palette and card strokes.
4. Living verification now describes page-scrolling cards rather than the
   retired horizontal/nested-scroll column model.

See each tied child's `decisions.md` for the seam-level choices.
