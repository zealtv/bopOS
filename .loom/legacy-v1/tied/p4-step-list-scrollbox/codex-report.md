Completed the task. No `.pd` files, commits, or Loom state outside this stitch

## Change 1 — vertically resizable scroll box

- Wrapped only `.show-rows` in `.show-rows-box`; the resize handle and add bar are
  siblings outside it.
- Chose a **480 px** default height. Dense rows are 32 px minimum plus a 3 px grid
  gap, so this exposes roughly 14 compact rows while retaining visible empty space
  for short shows.
- The box uses `overflow-y:auto`, `overscroll-behavior:contain`, native
  `resize:vertical`, and a 160 px lower bound.
- Native CSS resize carries pointer/desktop environments. A full-width 10 px
  `.show-rows-resize` bar with `touch-action:none` carries touch and other pointer
  environments where the native handle is unusable.
- Height and `scrollTop` live in module-level variables. `render()` reads live box
  geometry before replacing the DOM and restores it afterward. Hidden-tab startup
  measurements below the 160 px minimum are ignored, because a hidden box reports
  zero and must not erase the intended 480 px default.
- On custom pointer drag, the handle captures the pointer and updates the box
  inline. Show rebuilds are gated for the duration of the drag, then one pending
  render is applied on pointerup/cancel. This prevents the captured handle from
  being replaced during a 500 ms countdown rebuild.

## Change 2 — stable add bar

- `.show-add-bar` remains below the scroll box and resize handle, so its y-position
  is independent of item count.
- A pending step add records the prior item UIDs. On the server round-trip, the new
  step is identified, focused once, and scrolled with
  `scrollIntoView({block:"nearest"})`. The one-shot flag prevents later renders
  from yanking the list.
- Divider adds retain their existing focus behavior; only new steps use this flow.

## Change 3 — console first paint

Investigation found both `<details>` panels already omitted `open`, no persisted
toggle reopened them, and `.show-console-log` already had the intended
`max-height:240px`. The demonstrable first-paint defect was that summary counters
were blank until the first OSC event. Startup now explicitly closes both panels
and calls `renderConsole()` once, producing `0 shown · 0 seen` deterministically.
Normal incoming traffic then advances the counters, and toggle, pause, clear,
filter, and auto-scroll paths are unchanged.

## Change 4 — layout budgets

- Added `min-width:0` to the Show list grid child and kept the scroll box and touch
  handle full-width.
- The focused 768×1024 mobile/touch run verified the transport and add bar are in
  the viewport, the handle is usable, and document width does not exceed viewport
  width.
