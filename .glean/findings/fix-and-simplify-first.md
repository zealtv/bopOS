# Fix and simplify before adding

When choosing between adding a capability and repairing or removing something, repair first — Bob: *"I want to fix and simplify things before making them more complicated."*

The system works today and must keep working: prefer small ordered changes over rewrites. A defect found while designing a feature usually jumps the queue. A new warning, verb or setting added during a simplification pass needs Bob's ruling.
